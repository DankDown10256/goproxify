# Roadmap publique GoProxify

Vue allégée pour la communauté. Le détail interne n’est pas publié.

## Livré

### v0.3 — Sécurité avancée et observabilité _(septembre 2026)_

- **Conteneurs découverts → proxy** : bouton « Convertir en proxy » sur les conteneurs découverts (API, CLI `containers convert`, MCP) ; un proxy configuré passe toujours avant la route issue des labels du même hôte, qui reprend la main s'il est désactivé ou supprimé ; les tuiles signalent les proxys qui remplacent ou recoupent un conteneur ; détail d'un conteneur (config, santé, score, dernières requêtes), audit TLS / WAF / rate limit avec modèle de sécurité qui génère les labels à ajouter (Compose, Portainer, `docker run`, Kubernetes), proxys orphelins signalés — livré ; un conteneur arrêté, en pause ou qui redémarre reste affiché grisé « inactif » au lieu de disparaître, sans jamais entrer dans la table de routage — livré (Agent `0.16.0`, passerelle `0.99.0`, Admin `0.186.0`), Kubernetes (Service sans pod prêt) et les annuaires Consul et ECS compris (Agent `0.17.0`). ; la route issue des labels d'un conteneur (Docker, Portainer, Podman, Kubernetes, annuaires) se désactive et se réactive par hôte sans toucher au conteneur, la liste retenue par chaque passerelle et répliquée dans le groupe HA — livré (Admin `0.220.0`, passerelle `0.131.0`). Restent : surcouche sans conversion et actions de masse sur les tuiles
- **WAF avancé** : scoring anomalie, inspection requête (JSON/form/URI/headers/cookies) **et réponse** (CRS 951xxx), 13 jeux de règles OWASP CRS-4, règles custom hot-reload, métriques `gpx_waf_*`
- **WAF — nouveaux jeux de règles** : Java/Log4Shell (944xxx), RFI (931xxx), NodeJS/Prototype Pollution (934xxx), HTTP Request Smuggling (920xxx), Fichiers sensibles (930xxx), Fuites de données en réponse (951xxx)
- **Ephor** : moteur de détection comportementale stateful par IP — fenêtre glissante, ban immédiat sur signal, paramètres anti-DDoS configurables depuis l’UI (GlobalRPS, rate_window, rate_ban_threshold), detect mode, listes custom allowlist/denylist
- **Moteur de règles automatiques** : conditions pilotées (CVE critique, pic de bans, moteur silencieux, taux d’erreur, IP récidiviste) → actions (désactiver proxy, bannir IP, alerte, mode strict F2B) ; cooldown par règle, test dry-run, historique d’exécution
- **Menu Automatisation restructuré** : 4 entrées (Vue d'ensemble, Automatisations, Alertes, Journal) avec onglets ; vue d'ensemble, éditeur de flux avec simulation dry-run et journal filtrable ; store de modèles en onglet « Modèles » (18 modèles de flux paramétrables depuis Admin `0.139.0`)
- **Silences & maintenance** : fenêtres de temps qui suspendent l'exécution des actions du moteur de règles *et* l'envoi des notifications du moteur d'alertes (toutes les règles ou une sélection mêlant les deux), sans interrompre l'évaluation ni le journal ; les passerelles appliquent elles-mêmes les fenêtres des flux qu'elles exécutent, Admin coupé compris
- **Rejeu depuis le Journal** : une entrée d'historique en échec se rejoue en un clic, sans réévaluer la condition
- **Export/import YAML de l'automatisation** : règles, canaux et silences dans un seul document GitOps, réimportable (upsert par nom)
- **Canaux Slack, Microsoft Teams, Telegram, SMS (Twilio)** : quatre types de canal d'alerte supplémentaires, au même titre qu'email/webhook/ntfy/gotify
- **Registre de modules (pilote : canaux de notification)** : paquet commun `internal/modules` (manifestes, validation, secrets), les 14 types de canal migrés, API `/alert-channel-types`, MCP, CLI et formulaire pilotés par le manifeste (ADR 0007, Admin `0.120.0`). Familles Importer (`0.121.0`) et fournisseurs DNS (`0.122.0`) migrées ; Route 53, suppression des TXT OVH/Hetzner et fournisseurs nommés corrigés (`0.123.0`). Famille Discovery migrée (Admin `0.124.0` / Agent `0.9.0`). Famille cibles de déploiement migrée (Admin `0.125.0`). Famille AuthProvider migrée, avec correctifs fail-closed (Admin `0.127.0` / Edge `0.49.0`). Moteur de plugins WASM : moteur (Edge `0.53.0`, ADR 0008), installation et branchement sur les routes (Admin `0.131.0` / Edge `0.54.0`) livrés ; interface Admin, signature des paquets et sauvegardes livrées (Admin `0.132.0`) ; hooks de corps, état et réseau bornés, hook TCP/UDP, onglet de route, labels et dépôts de plugins livrés (Admin `0.134.0` / Edge `0.55.0` / Agent `0.9.3`) ; exemples compilés avec de vrais compilateurs livrés pour la requête (`path-guard` en TinyGo et en Rust), l'état (`rate-guard`), le corps (`body-redact`), le réseau (`token-check`) et TCP/UDP (`tcp-allow`), exécutés par la suite de tests, quatre d'entre eux livrés avec l'Admin et installables d'un clic sans dépôt (Admin `0.137.0`), plus Coraza (SecLang) en module livré avec l'Admin (Admin `0.138.0`), dont les refus sont tracés, comptés et peuvent bannir l'IP sous la source `plugin:coraza` (Admin `0.154.0` / Edge `0.69.0`), et mesure en charge sur une machine ; restent un SDK pour les langages, la mesure avec plusieurs passerelles et sur la durée, et une instance réutilisable si l'isolation entre requêtes peut être garantie autrement. Famille Action (moteur de règles) migrée (Admin `0.133.0`) ; actions à secret `webhook_signed` et `pagerduty`, secrets masqués dans toutes les sorties et export des canaux masqué (Admin `0.135.0`). Famille Detector (détecteurs par route : filtre IP, GeoIP, bot, WAF) migrée (Admin `0.128.0` / Edge `0.50.0`) ; Ephor, Fail2Ban et CrowdSec, moteurs globaux, ont des manifestes de configuration (validation, secrets masqués ; Admin `0.130.0` / Edge `0.52.0`) sans entrer dans la chaîne de middlewares
- **Regroupement anti-bruit** : une fenêtre de regroupement par règle d'alerte fusionne les événements similaires en une seule notification
- **Versionnage des règles avec retour arrière** : un instantané par modification, 20 versions conservées par règle, restauration en un clic
- **Escalades avec accusé de réception** : des paliers renotifient un événement non acquitté vers d'autres canaux, jusqu'à acquittement
- **Planifications (cron)** : déclenche une action du moteur de règles à heure fixe (expression cron 5 champs), indépendamment de toute condition — devenues des flux à déclencheur horaire (Admin `0.139.0`)
- **Approbation avant action** : une règle peut exiger qu'un admin approuve ou refuse son action avant exécution — devenue une étape de flux
- **Playbooks** : enchaîne action, attente, condition et approbation en une séquence, déclenchable comme une action de règle/planification ou manuellement — devenus des flux à lancement manuel
- **Flux d'automatisation unifiés (Admin `0.139.0`)** : règles, planifications et playbooks deviennent un seul objet, le flux (déclencheur condition / événement / horaire / manuel, garde-fou, étapes action, attente, si/sinon, approbation, appel d'un playbook, arrêt, variables). Éditeur de flux construit depuis le catalogue des briques, simulation d'un brouillon, modèles paramétrables rééditables ou détachables, condition sur les métriques relevées, exécutions qui survivent à un redémarrage de l'Admin, flux simples exécutés par les passerelles et envoyés à chaque modification (ADR 0009) ; changements affichés entre deux versions et modèle mis à jour depuis l'installation signalé (Admin `0.141.0`) ; seuil sur une métrique évalué par les passerelles sur leur propre trafic (Admin `0.142.0`, Edge `0.60.0`)
- **Page admin "Accès MCP"** : allowlist d'IP sources pour `/mcp` (réseaux privés par défaut), vue des utilisateurs porteurs d'un token, catalogue de scopes ↔ outils
- **IP client fiable** : les en-têtes `X-Forwarded-For` / `CF-Connecting-IP` / `X-Real-IP` ne sont crus que depuis un proxy de confiance (`GPX_TRUSTED_PROXIES`) — fin du contournement Fail2Ban/Ephor par IP forgée
- **MCP — allowlist de destinations backend** : `create_proxy` / `update_proxy` ne peuvent pointer que vers des destinations autorisées (réseaux privés par défaut), contre le détournement de trafic par prompt injection
- **MCP — contrôle d'accès complet** : chaque outil et chaque ressource exige le scope de sa route REST équivalente, plus le rôle admin quand la route est réservée aux admins ; un outil sans scope déclaré est refusé. Nouveaux scopes `alerts:write`, `domains:write`, `certs:write` : un scope de lecture ne permet plus d'écrire, via l'API comme via le MCP
- **MCP — liste d'outils à la mesure du client (Admin `0.148.0`)** : `tools/list` n'annonce que les outils autorisés au PAT, et `/mcp?toolsets=…` n'expose que certains groupes (proxies, observabilité, sécurité…), pour les modèles locaux à petit contexte
- **Écritures réservées aux admins, interface comprise** : certificats (dont pull tokens et cibles de déploiement), domaines, alertes et profils IP ne sont modifiables que par un admin, en session web comme par token API ; les snippets restent ouverts aux comptes disposant d'un droit d'écriture. L'interface masque ces actions aux autres comptes
- **Logs — réglages RGPD réservés aux admins** : rétention, anonymisation, pseudonymisation et effacement des logs ne sont modifiables que par un admin (scope `logs:write` pour un token API) ; anonymisation et pseudonymisation exclusives, l'anonymisation locale de la passerelle l'emportant toujours ; révélation d'une IP possible après désactivation de la pseudonymisation
- **RGPD — effacement par IP complet et rétention des bans** : l'effacement d'une IP supprime aussi ses bans, leur historique et son entrée du cache GeoIP (et lève ses bans sur les passerelles) ; la purge quotidienne applique `retention_ban_days` (730 jours) à l'historique et aux bans expirés, et la rétention des logs d'accès au cache GeoIP (Admin `0.162.1`)
- **RGPD — export d'accès, effacement jusque dans les passerelles, défauts protecteurs, dossier de conformité** : `goproxify logs subject-export` (Art. 15 et 20), effacement par IP rejoué sur les passerelles (access log, historique de bans), logs 90 jours et géolocalisation sans tiers par défaut, enregistrements du portail 90 jours, registre des traitements et notice d'information en modèles (Admin `0.163.0`, Edge `0.73.0`)
- **Logs — RGPD dans l'interface et la CLI** : choix du mode de protection des IP (entières, anonymisées, pseudonymisées) dans les réglages de la page Logs, révélation d'une IP pseudonymisée depuis le détail d'une entrée (super-admin, motif obligatoire), effacement par IP couvrant les entrées pseudonymisées ; `goproxify logs delete`, options CLI acceptées avec `-` ou `--`
- **Tableau de bord en trois vues** : Santé (verdict et actions à mener), Cockpit (indicateurs, courbe 1 h, passerelles, certificats) et Carte (origine du trafic par pays, blocages par couche, latence par passerelle)
- **Page Proxies** (ex-Trafic puis Routage) : tuile proxy et vue tableau refaites (hôte en titre, actions secondaires dans un menu ⋯, fonctions en icônes, métriques en ligne) ; modale de proxy unifiée, désormais en parcours d’une requête (sept étapes — Entrée, Sécurité, Routage, Transformation, Backends, Résilience, Observabilité —, un réglage à la fois, recherche Ctrl+K, bascule YAML ; WAF avec sélecteur de plateformes applicatives dans l’étape Sécurité ; Admin `0.150.0`) ; vues « état » (santé, KPIs, courbe) et « maître/détail » ; mode expert (interrupteur dans la modale : les réglages rarement utilisés sont masqués tant qu'ils ne sont pas configurés ; extension à toute l'interface prévue ; Admin `0.212.0`) ; création de proxy en mode Simple (cartes de protections), lignes dépliables, courbes alimentées par un historique de métriques côté Admin
- **Menu unifié Admin / passerelles** : un rail latéral (Admin + une pastille par passerelle, recherche au-delà de 6) remplace la liste de passerelles ; un seul menu (Proxies, Observabilité, Sécurité) commun, suivi de la section Plateforme (Admin) ou Passerelle (Portail Access, Tunnel L4, Paramètres) ; l’entrée « Trafic » devient « Proxies »
- **Traçage d’une IP ou d’un CIDR** : onglet Sécurité › Traçage IP — parcours chronologique d’une IP malveillante ou d’une plage sur une longue période (requêtes regroupées en épisodes, détections WAF/Ephor/CrowdSec, bans et débans, bans en cours, profils IP concernés) ; aussi en CLI (`security trace`) et MCP (`trace_ip`) (Admin `0.82.0`) ; raccourci « Analyser l’IP » depuis les bans, menaces, Ephor, Prism et les logs (Admin `0.83.0`), qui ouvre directement le traçage de l’IP, l’élargissement à la plage ou à l’ASN se faisant dans le parcours (Admin `0.156.2`) ; chronologie du plus récent au plus ancien, et chaque ban dit quel User-Agent l’a provoqué (Admin `0.207.0`, Edge `0.121.0`)
- **Profils IP : saisie manuelle et modèles** : modification d’un profil existant ; un profil peut être une liste d’IP/CIDR saisie à la main (en plus d’un feed), le formulaire propose des modèles de feeds (Bogons, blocklist.de, CINS Army) et explique la portée globale et la priorité `allow` sur `deny` (Admin 0.81.0)
- **Restauration sélective des snapshots** : le bouton *Restaurer* permet de choisir les entités à restaurer et le mode de conflit ; menu Sauvegardes réduit à Snapshots / Planification (Admin `0.80.0`)
- **Sauvegardes : destinations hors serveur (S3, WebDAV, dossier), vérification d’intégrité et alertes** : chaque snapshot est copié, relu et comparé ; alerte sur échec ou exécution manquée (Admin `0.105.0`)
- **Sauvegardes : clé de chiffrement gérée depuis l’interface** : génération, rotation sans perdre les anciens snapshots, révélation par le superadmin avec son mot de passe (Admin `0.111.0`)
- **Sauvegardes complètes** : config HA, état de chaque passerelle et de ses Agents, et historique (journaux, audit, bans) dans des sections chiffrées, restaurables par le superadmin (Admin `0.110.0`, Edge `0.39.0`, Agent `0.8.0`)
- **Sauvegardes : section secrets chiffrée** : avec `GPX_BACKUP_KEY`, les snapshots embarquent mots de passe, MFA, tokens, clés RGPD/ECH, CA interne et fichiers d’état pour restaurer une infrastructure complète (superadmin) (Admin `0.98.0`)
- **Recherche de fonctionnalités (Ctrl+K)** : palette de recherche dans la barre du haut (aussi `/`) pour retrouver n’importe quelle page de l’Admin ou d’une passerelle par titre ou mot-clé (WAF, ACME, SSO, sauvegardes…), retrouve aussi proxies, certificats, domaines, passerelles, snippets et utilisateurs par leur nom, filtrée selon le rôle (Admin `0.73.0`)
- **Menu Sécurité en onglets** (Synthèse, Vulnérabilités, Bans, Ephor, Score par proxy — note de A à F sur 9 contrôles), Synthèse unique (score, bans par source, menaces, timeline) et fenêtre « Moteurs de sécurité » à interrupteurs par capacité et page **Vulnérabilités** en vue Parc / Liste avec tiroir de détail, identique pour l’Admin et les passerelles, adaptée au mobile

### v0.2 — Architecture distribuée _(juillet – août 2026)_

- Reverse proxy distribué Admin / Passerelle / Agent (un binaire, trois modes)
- Relay passerelle→Passerelle multi-hôtes (Portainer / délégation)
- GoProxify Access (portail SSH / shell, 2FA, sessions TTL)
- Wizard architecture (toile, tickets QR / `curl|bash`, multi-passerelle / HA)
- Sécurité : MFA, CrowdSec bouncer, WAF, GeoIP, RBAC grants, SSO (OIDC/SAML/LDAP/GitHub)
- Tokens API utilisateur (PAT) + MCP server
- CLI opérationnel (`token`, `backup`, `alert`, `import`, `nodes`, `access`)
- Métriques Prometheus, Prism dashboard, Logs d’accès live
- **Observabilité complète** : instrumentation Prometheus de tous les services (backend health, peer sync, WAF, portal sessions, Admin HTTP, VulnScan, Rules Engine) — `docs/services.md`
- i18n EN / FR / ES / DE
- Quickstart Docker Compose + images GHCR (preview)
